# test-plan-authoring

**测试计划编写技能**：把测试计划写成「交给 Codex/Claude 等 AI 可直接执行的任务规格」。每个用例可追踪、可重放、可判定，测试数据可恢复，结果可统计，计划与报告严格分离。

> 即使用户没有明确说「测试计划」，只要涉及分层测试、回归清单、契约测试、E2E 视觉巡检、测试数据准备/清理，也应使用本技能。

## 触发条件

- 用户要求「写测试计划 / 测试方案 / test plan」
- 计划将交给 AI CLI（codex/claude）在测试机执行

## 核心机制

| 机制 | 说明 |
|---|---|
| 铁律（§0） | 先盘点后写数（禁沿用旧数字）、版本锚定（commit/产物/进程指纹）、数据可还原（无清理步骤的用例禁入计划）、数字可推导（报告数字能从用例 ID 对账）、未执行≠LIMITED |
| 六原则 | 用例可追踪 / 可重放 / 预期可判定 / 数据可恢复 / 结果可统计 / 计划与报告分离 |
| 状态五态 | PASS / FAIL / SKIP / LIMITED / 未执行；未执行独立计数，通过率=PASS/(PASS+FAIL)，实际覆盖率=executed/plan_total，两者必须同时给出 |
| 版本指纹 | commit SHA、构建时间、jar/class mtime、进程启动时间写入计划，执行前校验「源码变了但测的是旧产物」 |
| 清理门禁 | 执行后强制：重放 seed → 清 Redis 测试键 → 删 MinIO 测试对象 → 计数比对；失败路径也必须恢复（如改密失败后账号锁死要用 seed 恢复） |
| AI 执行者指令 | 顶部 §0 八条：端点以代码为准、按层串行、失败二分、禁中途注册、报告不写密钥、默认不自动提交、执行前版本指纹校验、执行后清理门禁 |
| 已知缺陷类 | 11 条回归项沉淀（统计卡窗口过滤、VO 字段改名同步链、MyBatis 别名映射、登录按钮文案 fallback、限流语义先读代码、networkidle 陷阱等） |

## 标准结构

§0 元信息 → §1 目标与范围（含需求覆盖矩阵）→ §2 环境与准入（服务/依赖/数据基线/版本指纹）→ §3 测试数据管理（fixture 表 + 清理门禁）→ §4 用例清单（ID/优先级/前置/步骤/期望/清理/证据/状态）→ §5 执行顺序与缺陷流程 → §6 风险与退出标准 → §7 报告模板。

用例编号：`{层}-{模块}-{序号}`（如 `API-AUTH-003`），发布后不可复用。
