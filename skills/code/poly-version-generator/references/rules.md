# 硬性规则与忽略清单

> 本文件是 `SKILL.md` 的参考附录，按需查阅。规则本体在
> `scripts/audit_layout.py` 的 `Profile` 定义里 —— 本文件是它的说明，
> 两者不符时以脚本为准，并重跑 `--emit-spec` 覆盖区文档的规范节。

## profile：source-snapshot

| | 值 |
|---|---|
| 版本是什么 | 同一既有项目 N 种风格**各改一遍**，每版是完整源码快照 |
| 版本根锁什么 | 只有 `src/` |
| `src/` 内部 | **不管** —— 照抄原项目的包结构 |
| 行数上限 | 无 |
| 交付源码用词检查 | 不做 |
| IDE 文件 | 不收录 |
| 典型区 | `poly-singleton`、`poly-prototype-shallow` |

> 区文档没写 `profile` 行时，可用 `--profile source-snapshot` 临时指定。

**不收 IDE 文件**（2026-09-22 定）。`.iml` 曾经是版本根的必需项，现已**撤掉**：
它是 IDE 元数据而非版本产物、本就可重新生成，锁它换不来「每版能独立编译运行」。

## 硬性规则（速查）

完整的树与逐条理由见 `项目总结.md` 第一节（由 `--emit-spec` 生成）。要点：

| 规则 | 原因 |
|------|------|
| 区根只有一份 `项目总结.md`，版本目录里**不放任何 md** | 四份 md 并存时改一处漏一处；旧文档会让人不知道哪份是真的 |
| 版本根**只有 `src/`** | 快照型只锁 `src/`，里面照抄原项目；别的（文档/探针/报告/构建产物）都不是版本产物 |
| **不收 IDE 文件**（`.iml`/`.iws`/`.ipr`/`.idea/`） | 那是 IDE 本机状态，可重新生成，不是交给老师的东西 |
| **禁止改 `src/` 内任何源码** | 快照须与原分支逐字一致；就地改会让 `diff` 混入手工痕迹，五版对照的可信度就没了 |
| 不锁代码怎么写 | 抽象方式、模块拆分、命名细节属风格差异，正是对照的对象 |

## 审计不看的东西

编译产物与临时文件一律忽略，**所以 `javac` 跑过之后再审计也能 PASS**：
`*.class`/`*.jar`、`bin/`/`out/`/`target/`/`build/`、`__pycache__/`/`.venv/`、
`截图/`（截图工具的产出）、`~$*`/`.*~`。

清单在脚本的 `IGNORE_DIRS` / `IGNORE_GLOBS` 里。**增删时同步看一眼仓库根 `.gitignore`** ——
两处覆盖的类别应当一致，否则会出现「git 不管、审计也放行」或反过来「git 不管、审计却报错」的错位。
