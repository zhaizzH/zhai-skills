# 硬性规则与忽略清单

> 本文件是 `SKILL.md` 的参考附录，按需查阅。规则本体在
> `scripts/audit_layout.py` 的 `Profile` 定义里 —— 本文件是它的**说明**，
> 两者不符时以脚本为准，并重跑 `--emit-spec` 覆盖区文档的规范节。

**快照型为什么不做那几类检查** —— 不是「可以糊弄」，是那几条的**前提不成立**：

1. 快照是已冻结的物料，本就分包多文件（原项目十几个文件），「实现必须单文件」无意义。
2. 快照逐字复制自原分支，**不许就地改**，所以「改掉违规用词」这个动作本身被禁止。
3. 用词检查会误伤：「契约」在中文源码里是普通词（接口约定），不是本项目文档的简称专属 ——
   子串检查分不出这两种用法，快照型因此一律不跑它。

## 硬性规则（速查）

完整的树与逐条理由见 `项目总结.md` 第一节（由 `--emit-spec` 生成）。要点：

**通用**

| 规则 | 原因 |
|------|------|
| 区根只有一份 `项目总结.md`，版本目录里**不放任何 md** | 四份 md 并存时改一处漏一处；旧文档会让人不知道哪份是真的 |

**`single-file` 专有**

| 规则 | 原因 |
|------|------|
| 入口名固定（缺省 `<Xxx>Experiment.java`；区文档 `entry` 可覆盖） | 跨版本 `diff` 的锚点 |
| `report/` 目录及 `parse.py`/`facts.py`/`render.py` 三名固定 | 同「不同人的同名文件能直接对照」 |
| 报告 docx 必须在**版本根目录** | 便于统一打包 |
| `_make_report.py` / `_pack.py` 在版本根，不藏进子目录 | 同上；打包入口要能跨版对照 |
| `run_output.txt` 必须由运行重定向产生 | 手写 = 数据作废 |
| **代码实现必须单文件**（核心约束：只许入口 + 声明的额外实现文件，递归查子目录） | 差异落在文件内部，不靠拆文件 |
| **入口文件 ≤ `max_lines` 行**（缺省 150，**物理行**，注释与空行都算；`0` = 不限） | 不许写长；与单文件合起来逼出「同一文件内的组织差异」 |
| **入口文件必须存在**（行数上限只查入口，缺了就无从生效，故报 FAIL） | 防止把 `entry` 写错或写成匹配不到文件的 glob，让行数上限**静默**失效 |
| 文档、IDE 文件与**未声明**的产物都不算数 | 产物清单由区文档的 `required`/`submit` 决定，脚本只查「声明的在不在」 |
| `test/` 自由增删 | 风格差异的落点 |
| `README.txt` 只写交付内容，不得提开发文件 | 它被逐字复制进提交包，提了就是悬空引用（有机器检查） |
| `README.txt` 不写版本号、不与其他版本比较 | 提交包是给老师看的，版本号是内部对照概念 |
| **交付源码里不得出现版本号/风格名/设计模式名/「契约」**（有机器检查，`java_checks` = `off` 可关） | 每份要能当独立的人写的东西交出去；出现这些词＝暴露「同一批人的多版本实验」 |
| **文件头不得抄「编译 / 运行」命令行**（有机器检查，`java_checks` = `off` 可关） | 那是 `README.txt` 的职责，夹在注释里像 README 摘抄；行内提到 `javac` 不算 |
| 区根 `提交/<版本名>/` 各恰为 `submit` 声明的那几个文件（缺省 5 个，`submit` 留空则本区不生成提交包） | 各份要能各自独立交出去；提交包不能混进开发文件，多了少了都容易被忽略 |

**`source-snapshot` 专有**

| 规则 | 原因 |
|------|------|
| 版本根**只有 `src/`** | 快照型只锁 `src/`，里面照抄原项目；别的都不是版本产物 |
| **不收 IDE 文件**（`.iml`/`.iws`/`.ipr`/`.idea/`） | 那是 IDE 本机状态，可重新生成，不是交给老师的东西；仓库根的 `.idea/`、`.iml` 同理不归本技能管 |
| **禁止改 `src/` 内任何源码** | 快照须与原分支逐字一致；就地改会让 `diff` 混入手工痕迹，五版对照的可信度就没了。要改写法回源区改、重新导出 |
| 不做单文件/行数/用词/README/`提交/` 检查 | 前提不成立（见上文「两套 profile」），不是放宽 |

## 审计不看的东西

编译产物与临时文件一律忽略，**所以 `javac` 跑过之后再审计也能 PASS**：
`*.class`/`*.jar`、`bin/`/`out/`/`target/`/`build/`、`__pycache__/`/`.venv/`、
`截图/`（截图工具的产出）、`~$*`/`.*~`。

清单在脚本的 `IGNORE_DIRS` / `IGNORE_GLOBS` 里。**增删时同步看一眼仓库根 `.gitignore`** ——
两处覆盖的类别应当一致，否则会出现「git 不管、审计也放行」或反过来「git 不管、审计却报错」的错位。
