# 排障

> 「现象 → 原因与处理」表。多数条目由审计器的报错文案直接触发。

## 审计输出长什么样

```
审计 poly-singleton-demo/ —— 共 5 个版本
profile：single-file（一个目标 N 种风格**各写一遍**，代码是实现物，故约束单文件与行数。）
映射：Xxx → SingletonDemo，报告名 → 实验 单例模式演示.docx

√ v01  PASS
× v02  FAIL
    - 多出顶层文件 setup.py（不在本 profile 的规范内；校验脚本放 test/）

× 区根文档  FAIL
    - 区根还有 PLAN.md —— 现在只留一份 项目总结.md，把 PLAN.md 的内容并进去后删除该文件

√ 提交/  PASS（5 个版本，每份 5 个交付文件，无多余、无缺失）
```

## 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 审计报「区根还有 `CONTRACT.md`」 | 四份 md 已合并成 `项目总结.md` 一份。把内容并进对应四块后删掉旧文件 |
| 审计报「版本目录里不该有 `MANIFEST.md`」 | 每版不再各带一份文档，「本版有什么、本版取舍、校验记录」并进 `项目总结.md` 第三块 |
| 审计报「缺必需文件 MergeSortExperiment.java」 | `项目总结.md` 里没写 `<Xxx>` 映射行，或写成了别的形式。按上面第 1 步的格式补上 |
| 审计结果和预期差很多（五版一起报十几条 `.java` 违规） | **profile 认错了**。快照区被当成 `single-file` 审了。检查 `项目总结.md` 里有没有 `` - `profile` = `source-snapshot` ``，或本次加 `--profile source-snapshot` |
| 审计提示「`<模块>` 映射行已失效」 | `.iml` 不再进版本区（2026-09-22 起）。删掉区文档里那行 `` - `<模块>` = `PlanWar` `` 即可 —— 它现在什么都不指向 |
| 审计提示「`required` 里没有入口文件 `XxxYyy.java`」 | `required` 一旦声明就只查列出的项，入口会因此失去「缺必需文件」保护、行数上限也失去落点。把入口名加进 `required` 清单 |
| 审计提示「`required` 里没有 `_pack.py`」 | 声明了 `submit` 却不让打包入口存在。把 `_pack.py` 加进 `required`，或改用别的打包方式 |
| 想给某版单独跑一遍看看（要 IDE 能编译） | 别往 `vNN/` 里放 `.iml`。用原项目的模块，或在 IDE 里把该版 `src/` 手动标成 source root —— 版本区审计不看你这么做，但目录里也不该留下痕迹 |
| `_pack.py` 报「本版提交包已存在」 | 那一版已经打过包了，脚本拒绝静默覆盖（怕删掉包里手工补的东西）。确认要重建（会先删目录再重填）再加 `--force`；不确定就别加 |
| 审计报「README.txt 里出现了开发侧的名字」 | README 是交付说明，会被逐字复制进提交包，而包里没有 `项目总结.md`/`report/`/`test/`。把那些句子（完整文件清单、重跑步骤）挪进 `项目总结.md` 第三块 |
| 审计报「提交包缺文件 xxx」 | 用该版 `_pack.py` 重新生成。若是缺报告 docx，先跑 `_make_report.py` |
| 审计报「提交包里多出文件 / 不该有子目录」 | 混进了开发文件。删掉后重新 `_pack.py`（它只复制 5 个交付物，不会自己多带） |
| 审计报「缺 提交/v03/」 | 那一版还没打包。`cd v03` 跑一次 `python _pack.py` 即可，不影响已打好的其它版 |
| 某版更新了源码/报告，提交包还是旧的 | `_pack.py` 只从**自己所在的版本目录**取文件。`cd` 进那一版重跑并加 `--force`；只重建这一版，其它版不受影响 |
| 报告 docx 里还没插截图，提交包就先打了 | 顺序反了。先跑 `Screenshot.java` 截图、把图插进 docx，**再** `_pack.py` —— 否则提交包里的报告没有截图 |
| 审计报「多出顶层文件 xxx」 | 该文件不在 `Profile.spec` 里。要么它是源文件 → 并进入口文件（`single-file` 禁止多文件）；要么它确实是本版必需产物 → 加进脚本的 `SPEC` |
| 审计报「多出 Java 源文件 xxx」 | 违反单文件规则（仅 `single-file`）。把辅助类改成入口文件的嵌套类，或直接并进入口类；不要挪进子目录 —— 递归检查照样报 |
| 审计报「xxx 有 N 行，超出上限」 | 违反行数上限（仅 `single-file`）。**精简实现**（合并冗余类、缩短命名、去掉中间变量），不是删注释凑数 —— 但注释确实该写得克制。上限值取自 `max_lines` 配置行，缺省 `150`，按物理行（含注释与空行）计 |
| 想改行数上限 | 在区文档加一行 `` - `max_lines` = `260` ``（`0` = 不限**入口文件**），然后重跑 `--emit-spec` 覆盖 `项目总结.md` 第一节。**不要手改生成节**。只在**所有**区都要换缺省时才动脚本里的 `JAVA_MAX_LINES` |
| 审计报「入口文件 xxx 不存在（区文档 `entry` 指定）」 | `entry` 指的名字在版本目录里找不到。行数上限只查入口，入口不在就无从生效 —— 所以这是 FAIL 而不是静默跳过。核对 `entry` 的拼写（非 Java 区必须写，如 `` - `entry` = `main.py` ``） |
| `report/` 明明没用到却报「缺必需目录」 | 仅 `single-file`：`report/` 是必需目录。哪怕某版就把逻辑写在 `_make_report.py` 里，也要建 `report/` 并放三个文件（内容可以是薄封装）—— 否则失去跨版对照锚点 |
| 改完树，`项目总结.md` 与审计结果不一致 | 树只该在脚本里改一次，然后重跑 `--emit-spec` 覆盖第一节。不要手改生成节 |
| 审计输出里的标记显示成 `?`（如 `? v01 FAIL`） | GBK 控制台编不出 `⚠`/`√`。审计器已把「异常退出」降级为「个别字符替换」，**结论照样是完整跑完的**；想让标记完整显示就加 `PYTHONIOENCODING=utf-8`，或直接 `-o` 写文件。改造前这里是真的 `UnicodeEncodeError` 中断，看到 `?` 说明拿的是旧脚本 |
| 几版的正文还在讲**已被删掉或改名的类** | 精简代码后忘了回头改文案。改完源码后把正文里出现的每个类名/方法名拿去源码 grep 一遍 —— 布局审计与报告校验都抓不到这一类 |
| 审计报「交付源码里出现了 `v04` / `结构化版` / `契约`」 | 横向对照的内部概念漏进交付物了（仅 `single-file`）。改**表达方式**而不是删信息：`契约要求三者不得共用归并` → `三种算法各自归并，不共用`；`v04「结构化版」` → 直接描述这版怎么组织（或整句删掉，头部只留实验名）。**这一条也适用于 report 层里会被渲染进 docx 的段落** |
| 审计报「头部第 N 行的『编译/运行』命令行」 | 文件头抄了 `编译：javac …` / `运行：java -Dstdout…`。删掉即可 —— 编译运行方法在 `README.txt` 里（`Screenshot.java` 也一样，它每版逐字节相同，五份要一起改） |
| 几版的段落开头/收尾句式雷同 | 防雷同的规则里**举例句**等于给模板。定稿前把各版首句、分段编号并排比一遍；机器不查相似度 |
