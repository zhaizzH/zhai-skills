# 生成提交包（每版各一份）

> 本文件是 `SKILL.md` 的参考附录。仅对声明了 `submit` 配置行的区适用。

### 3. 生成提交包（每版各一份，仅声明了 `submit` 的区）

各版要能以**各自独立的身份交出去**，所以**每版都有自己一份完整交付物**。
在每版目录里各跑一次它的 `_pack.py`：

```bash
cd <版本区>/v01                            # 脚本从自身位置定位版本，不看当前目录
python _pack.py                            # 复制交付物到区根 提交/v01/
python _pack.py --force                    # 本版已打包过，确认要重建时才加

cd ../v02 && python _pack.py               # 其余各版同理，产出 提交/v02/ …
```

- 交付物清单由 `submit` 配置行声明（`single-file` 缺省 5 个：入口文件、`Screenshot.java`、
  `run_output.txt`、`README.txt`、报告 docx）。**开发文件一律不进**。
- **`提交/` 在区根，下按版本名分目录。** 各版一份，互不覆盖：`_pack.py` 只重建
  **自己那一版**的子目录，顺序无所谓。
- `_pack.py` 拒绝静默覆盖**自己那一版**：`提交/<本版名>/` 已存在而没给 `--force`
  就报错退出 —— 防止手滑把包里手工补过的东西（例如插好图另存的 docx）删掉。
- 各版的 `_pack.py` **内容逐字节相同**（跨版 `diff` 的锚点）。要改就各份一起改。
- 截图是**先手动补进 docx、再打包**；`_pack.py` 不会替你去截图。补完图要重跑该版。
- **`README.txt` 是交付说明，不是文件清单。** 它会被逐字复制进 `提交/`，
  而包里没有 `项目总结.md`、也没有 `report/` 与 `test/` ——
  在 README 里列这些名字就成了指向不存在文件的悬空引用。这条有机器检查。
- 各版 `README.txt` **不要写版本号**（版本号是横向对照的内部概念，属于 `项目总结.md`）。
