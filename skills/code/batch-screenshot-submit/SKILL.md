# 多版本对照的批量截图与提交打包

## 这个技能解决什么

`poly-version-generator` 产出的版本区长这样：一个实验 N 个版本（`v01`…`v05`），
每个版本是一份完整源码。交作业时要的是：

> **每个版本各一份源码 zip + 各一张运行截图，按实验归位成提交包。**

手工做是 8 个实验 × 5 版 = 40 次「编译、运行、截图、改名、打包」，
必然出错，而且出错时常常**看不出来** —— 最典型的是截图截出一张纯黑窗口，
资源其实没加载，但图看着「有东西」。

本技能把这件事压成一条命令，并在中间加三道**必须过**的检查：
代码能编译、截图不是空白、截图里的字真的画出来了（不是豆腐块）。

## 唯一真源

```
batch-screenshot-submit/scripts/capture.py
```

本文件是它的说明。脚本行为与本文件不符时以脚本为准。

## 一条命令

```bash
S=batch-screenshot-submit/scripts/capture.py
python $S <仓库根>                                  # 全部 <项目>/poly-*/ 版本区
python $S <仓库根> --area 04-FactoryPattern/poly-factory-car
python $S <仓库根> --dry-run                        # 只列计划，不编译不截图
```

对每个版本区的每个 `vNN`，依次做：

0. **确认 JDK 版本**（交互式跑时会先问）。理由：`javac` 默认拿 PATH 上那个，
   而一台机器常装好几个。用错版本是**静默失败**：高版本 JDK 编低版本目标的源码，
   本机一切正常、到目标机才 `UnsupportedClassVersionError`。
   版本定下后用 `javac --release N` 钉住，并把同一个 `javac` 传给 `check_code.py`，
   保证前置检查与正式编译用同一个编译器。
1. **前置检查**：跑 `poly-version-generator/scripts/check_code.py`。
   编译不过、同类名冲突、out 被污染 → **整体中止**，不产出半个提交包。
   检查用**每区专属的 out 根**（`out/check-<项目>-<区名>/`）：`check_code.py`
   的路径形状是 `<out-root>/<vNN>/`，而各区的版本名都是 `v01`…`v05`；
   共用一个 out 根时 A 区的 `out/v01` 会被 B 区的检查当成「本版 out 里出现了
   源码之外的类」—— 假阳性，且正好掩盖真实的污染。
2. **编译**：整套编译（`$(find src -name '*.java')`，绝不只编入口）到
   `out/shot-<项目>-<区名>-<版本>/`，**每版一个独立 out**。
3. **运行并截图**：
   - 控制台程序（源码里没有 `javax.swing`/`java.awt.Graphics`）→ 抓 stdout，用 PIL 渲染成图；
   - GUI 程序（Swing）→ 注入 `ScreenshotHelper`（编到 `out/_helper/`，**不写进 `src/`**），
     反射调用原 `main`，等窗口出现后 `Robot` 截**窗口区域**，截完退出。
4. **校验截图**，两道都要过：
   - **非空白**：像素标准差低于阈值 = 纯色图 → 该版 FAIL；
   - **字形齐全**（控制台图）：渲染前拿**本次真实输出**的字符集去验字体字形，
     画不全就换下一款字体；一款都挑不出来 → 明确报错，该版 FAIL。
     只查空白查不出乱码 —— 豆腐块图的像素标准差约 28，能轻松通过空白检查。
5. **打包归位**：`src/**` 打成 zip（含 `img/`、`.wav` 等资源），与截图一起放进
   `<仓库根>/提交/`。摆在哪个子目录取决于项目的提交布局，见下节。

退出码 0 = 全部成功；1 = 有失败，**此时提交目录不被产出或更新**。

## 两种提交布局

| 布局 | 产物路径 | 谁用 |
|---|---|---|
| **默认（按区）** | `提交/<项目>/<区名>/v01-src.zip` + `v01.png` | 其余项目 |
| **转置（按版本）** | `提交/<项目>/v01/<题号>/src.zip` + `screenshot.png` | `TRANSPOSED_PROJECTS` 里登记的项目（现为 `04-FactoryPattern`） |

默认布局一行是「一个区的一个版本」；转置把**区与版本两个维度对调**，一个 `vNN`
目录下横排该项目的各个题目。转置的前提是「同一项目里的多个区是同一批作业的不同题」，
所以只对这类项目开启 —— 单区项目（如 `01-PlanWar`）转置没有意义。

```
<仓库根>/提交/
├── 01-PlanWar/poly-singleton/          (默认布局)
│   ├── v01-src.zip   v01.png
│   └── …             (v02 v03 v04 v05)
└── 04-FactoryPattern/                  (转置布局)
    ├── v01/{1,2,3}/src.zip + screenshot.png
    └── …             (v02 v03 v04 v05)
```

### 题号从区文档读（转置项目必填）

转置布局下，一个区落在哪个 `<题号>/` 由区根 `项目总结.md` 里的一行决定：

```markdown
- `slot` = `1`
```

- **必须独立成行**。正文里顺带写到的 `` `slot` = `1` `` 不算配置 ——
  否则正文提一句就会静默改掉产物落点。
- 列表符号与 `>` 引用块前缀都可省（配置行常写在提示块里）。
- 值只收字母、数字、`_`、`-`：题号要当目录名，含 `/` 或 `..` 会把产物写到提交树外面。
- 这一行**要写在 `audit_layout.py --emit-spec` 生成区块之外**（标题下、生成注释前），
  否则重跑生成会把它抹掉。

转置项目里**没声明 `slot` 就直接 FAIL** —— 题号决定目录名，猜错等于把包放到错位置，
而且外观完全正常、看不出来。非转置项目声明了会被忽略，但会打印一句提醒（不静默吞配置）。

同一个项目里两个区声明同一题号也会 FAIL：后写的会盖掉前写的。

### 转置归位是「等齐再写」

同一个 `vNN` 目录由多个区共同写入，所以转置项目的落盘**推到最后**、等项目所有区都成功
才写：某区单独落盘会在提交树里留下半棵树（`v01/` 里只有 `1/`、缺 `2/`）。

归位时**只替换自己那个题号目录**，不动项目的其余部分 —— 这样 `--area` 单跑一个区
不会顺手删掉本轮没处理的其它题号。默认布局则是整区目录先删后建（该目录是本区独占的，
重建才能清掉上一轮多出来的文件）。

## 四条不可省的设计（改脚本时别删）

| 设计 | 不这么做会怎样 |
|---|---|
| **一版 = 一个 out 目录 = 一个工作目录** | 多版常复用同名包与默认包 `Main`，共用 out/cwd 时 javac/java 会挑错类，或从兄弟版本拉错实现 |
| **GUI 辅助类编到 `out/_helper/`，不进 `src/`** | `source-snapshot` 类版本区禁止改快照源码；写进 `src/` 会污染对照基线，`diff` 出来的差异混入手工痕迹 |
| **截图必须校验非空白** | 资源没加载时窗口是纯黑/纯白，不校验就会把空图当成成功交付 |
| **转置项目的题号从区文档读，不写死也不猜** | 题号是产物目录名；猜错（默认成 `1`）会把包放到错位置，而外观完全正常 |
| **渲染字体必须先验字形** | 字体写死 Consolas 时中文全渲染成豆腐块，而豆腐块图**能通过空白检查** —— 缺陷看着「有东西」，静默交付。挑不出字体要明确报错，**宁可失败，不可交付乱码** |

### 控制台图为什么不截真终端

控制台输出是用 PIL **渲染**的，不是截真实终端窗口。这是有意为之：真实终端截图
受字体、尺寸、主题影响，同一份输出在不同机器上长得不一样，**不可复现**；
渲染则给定字体与参数就必然产出同一张图。

不要为了「看起来更真」改成截终端 —— 那会用可复现性换一个已经解决了的问题，
而且重新把中文豆腐块的风险引回来（终端用什么字体就出什么图，不再是本技能管得住的）。

## 支持的两种版本区布局

| 布局 | 源根 | 例 |
|---|---|---|
| 标准（新） | `vNN/src/` | 绝大多数版本区 |
| 旧布局 | `vNN/` 本身 | `poly-singleton-demo`（`vNN/*.java`，无 `src/`） |

旧布局**只兼容、不迁移** —— 技能禁止改快照区源文件，布局债该单独修。

## 前置条件

- **JDK**（`javac`/`java` 在 PATH 上，或用 `--jdk <JDK_HOME>` 指定）。
  无 JDK 时编译一步会直接失败；交互式跑时会先问用哪个版本。
- **Python 包 `PIL`**（Pillow）：渲染控制台图与校验非空白都要它。
  `python -m pip install pillow`。
- **有可用桌面的环境**（GUI 截图用 `java.awt.Robot`）。无桌面会报
  「找不到可见窗口」并给出 `-Djava.awt.headless=false` 的提示。
- 版本区的 `poly-version-generator` 得认得出它声明的 profile
  （如 `source-snapshot`）；认不出时用 `--skip-check` 绕过前置检查，但**那是绕过**，
  该修的是 profile 定义。

## 常用参数

| 参数 | 作用 |
|---|---|
| `--area <相对路径>` | 只处理指定版本区，可重复 |
| `--dry-run` | 只列「每版是什么类型、入口类、文件数」，不编译不截图 |
| `--skip-check` | 跳过 `check_code.py` 前置检查（布局债未清时的逃生口） |
| `--jdk <JDK_HOME>` | 指定 JDK 目录（含 `bin/javac`）。优先于 PATH，指定后不再提问 |
| `--jdk-version N` | 目标主版本号（如 `21`），传给 `--release`；高于实际编译器时直接报错 |
| `--no-prompt` | 即使交互也不提问 JDK（脚本/CI 用） |
| `--javac` / `--java` | 分别指定编译器/执行器路径 |
| `--out-root` | 编译输出根，默认 `<仓库根>/out` |
| `--submission-root` | 提交目录根，默认 `<仓库根>/提交` |
| `--python` | 指定 python（跑 `check_code.py` 用） |

### JDK 版本是怎么定的

优先级：`--jdk` > `--javac`/`--java` 显式指定 > **交互式提问**（仅当 stdin 是终端）> PATH。

提问时会把 PATH 上探测到的版本当默认值（回车即采用），并把目标版本用 `--release N`
钉住。**非交互（管道、CI）不会提问** —— 否则脚本会卡在等输入上；此时走到 PATH 分支。

想脚本化又不想靠 PATH 的话，用 `--jdk-version N` 或 `--jdk <JDK_HOME>`。

> 要装多个 JDK、按需切换时，`--jdk <JDK_HOME>` 最可靠：它直接指到目录，
> 不依赖 PATH 当前指向哪个。

## 失败时怎么读输出

每个版本区打一张表，失败项逐条列出。对照处理：

| 症状 | 原因 |
|---|---|
| `找不到含 static void main 的类` | 该版没有入口，或入口写法特殊（如用了 `public static void main(String… args)` 之外的签名） |
| `编译失败` | 源码问题。先单独跑 `check_code.py` 拿到干净的编译错误 |
| `截图是纯色/空白` | 资源没加载。确认 `-cp` 含 `src/`、cwd 是版本根（`AssetLoader` 两条回退路径依赖它们） |
| `找不到能完整渲染本输出的字体` | 候选表里的字体都缺本次输出用到的字形（常见于输出含中文），报错里会列出每款各缺什么。装一款中文字体（如 SimHei）到系统字体目录，或把字体路径加进 `CONSOLE_FONT_CANDIDATES`。**不要靠改回写死字体绕过** |
| `找不到可见窗口` | 程序没起来（异常早退），或在无桌面环境运行 |
| `GUI 进程超时` | 程序不是启动后就常态显示（如需要按键才开窗口）。调大 `RUN_TIMEOUT_SECONDS`，或给它加参数 |
| `运行期报错` | 控制台程序抛异常了。stderr 里的异常会原样带出来 |

## 调参

脚本顶部是常量区，都有注释：预热时长、超时、渲染图尺寸与字号、空白判定阈值、
字体候选表。
**空白判定阈值别调高** —— 调高会把「资源没加载的黑图」放行，那正是这道检查要拦的。

### 字体候选表 `CONSOLE_FONT_CANDIDATES`

按优先级取第一款能画全本次输出的。顺序不能随意调
（下表为 `CONSOLE_FONT_SIZE = 16` 下实测的 advance width）：

| 字体 | ASCII 宽 | 汉字宽 | 比值 | 后果 |
|---|---|---|---|---|
| `consola.ttf` | 9 | 9 | 1.000 | **无 CJK 字形**，中文全豆腐块；纯 ASCII 输出时最好看 |
| `simhei.ttf` | 8 | 16 | **2.000** | 汉字占两列，表格对齐正确 ✅ |
| `simsun.ttc` | 8 | 16 | **2.000** | 同上 ✅ |
| `msyh.ttc` | 11 | 16 | 1.455 | ASCII 比例宽度，汉字不占整两列，表格列错位 ⚠️ 只作兜底 |

判定表格会不会错位只看一个数：**汉字宽 ÷ ASCII 宽是否恰为 2**。
恰好为 2 时一个汉字正好顶两个 ASCII 位，靠空格对齐的表格才对得齐。

`poly-singleton-demo` 这类输出靠「汉字占两列」的空格对齐表格，所以黑体/宋体
必须排在雅黑前面。

**改候选表时必须验字形**：只 `truetype()` 打开成功不算数 —— Consolas 也能打开，
只是画中文时全出方框。判定办法是把每个待测字符渲成位图，与「字体肯定没有的码位」
（`chr(0xFFFF)`）的位图逐字节比对，位图相同即走了 `.notdef` 分支。

## 与其它技能的分工

| 技能 | 管什么 |
|---|---|
| `poly-version-generator` | 版本区**放在哪、叫什么**（目录布局）；本技能的前置检查由它的 `check_code.py` 提供 |
| 本技能 | 让版本区**跑起来、截到图、打成可提交的包** |
| 报告类技能 | 交付说明、实验报告正文 |

本技能**不判断代码写得好不好**，也不改版本区里的任何源文件。
