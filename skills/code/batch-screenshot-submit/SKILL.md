# 多版本对照的批量截图与提交打包

## 这个技能解决什么

`poly-version-generator` 产出的版本区长这样：一个实验 N 个版本（`v01`…`v05`），
每个版本是一份完整源码。交作业时要的是：

> **每个版本各一份源码 zip + 各一张运行截图，按实验归位成提交包。**

手工做是 8 个实验 × 5 版 = 40 次「编译、运行、截图、改名、打包」，
必然出错，而且出错时常常**看不出来** —— 最典型的是截图截出一张纯黑窗口，
资源其实没加载，但图看着「有东西」。

本技能把这件事压成一条命令，并在中间加两道**必须过**的检查：
代码能编译、截图不是空白。

## 唯一真源

```
batch-screenshot-submit/scripts/capture.py
```

本文件是它的说明。脚本行为与本文件不符时以脚本为准。

## 一条命令

```bash
S=batch-screenshot-submit/scripts/capture.py
python $S <仓库根>                                  # 全部 <项目>/poly-*/ 版本区
python $S <仓库根> --area 04-FactoryPattern/poly-factory-car
python $S <仓库根> --dry-run                        # 只列计划，不编译不截图
```

对每个版本区的每个 `vNN`，依次做：

1. **前置检查**：跑 `poly-version-generator/scripts/check_code.py`。
   编译不过、同类名冲突、out 被污染 → **整体中止**，不产出半个提交包。
   检查用**每区专属的 out 根**（`out/check-<项目>-<区名>/`）：`check_code.py`
   的路径形状是 `<out-root>/<vNN>/`，而各区的版本名都是 `v01`…`v05`；
   共用一个 out 根时 A 区的 `out/v01` 会被 B 区的检查当成「本版 out 里出现了
   源码之外的类」—— 假阳性，且正好掩盖真实的污染。
2. **编译**：整套编译（`$(find src -name '*.java')`，绝不只编入口）到
   `out/shot-<项目>-<区名>-<版本>/`，**每版一个独立 out**。
3. **运行并截图**：
   - 控制台程序（源码里没有 `javax.swing`/`java.awt.Graphics`）→ 抓 stdout，用 PIL 渲染成图；
   - GUI 程序（Swing）→ 注入 `ScreenshotHelper`（编到 `out/_helper/`，**不写进 `src/`**），
     反射调用原 `main`，等窗口出现后 `Robot` 截**窗口区域**，截完退出。
4. **校验截图非空白**：像素标准差低于阈值 = 纯色图 → 该版 FAIL。
5. **打包归位**：`src/**` 打成 zip（含 `img/`、`.wav` 等资源），与截图一起放进
   `<仓库根>/提交/<项目>/<区名>/`。

产物形状：

```
<仓库根>/提交/
├── 01-PlanWar/poly-singleton/
│   ├── v01-src.zip   v01.png
│   ├── v02-src.zip   v02.png
│   └── …             (v03 v04 v05)
└── 04-FactoryPattern/poly-factory-car/…
```

退出码 0 = 全部成功；1 = 有失败，**此时提交目录不被产出或更新**。

## 三条不可省的设计（改脚本时别删）

| 设计 | 不这么做会怎样 |
|---|---|
| **一版 = 一个 out 目录 = 一个工作目录** | 多版常复用同名包与默认包 `Main`，共用 out/cwd 时 javac/java 会挑错类，或从兄弟版本拉错实现 |
| **GUI 辅助类编到 `out/_helper/`，不进 `src/`** | `source-snapshot` 类版本区禁止改快照源码；写进 `src/` 会污染对照基线，`diff` 出来的差异混入手工痕迹 |
| **截图必须校验非空白** | 资源没加载时窗口是纯黑/纯白，不校验就会把空图当成成功交付 |

## 支持的两种版本区布局

| 布局 | 源根 | 例 |
|---|---|---|
| 标准（新） | `vNN/src/` | 绝大多数版本区 |
| 旧布局 | `vNN/` 本身 | `poly-singleton-demo`（`vNN/*.java`，无 `src/`） |

旧布局**只兼容、不迁移** —— 技能禁止改快照区源文件，布局债该单独修。

## 前置条件

- **JDK**（`javac`/`java` 在 PATH 上）。无 JDK 时编译一步会直接失败。
- **Python 包 `PIL`**（Pillow）：渲染控制台图与校验非空白都要它。
  `python -m pip install pillow`。
- **有可用桌面的环境**（GUI 截图用 `java.awt.Robot`）。无桌面会报
  「找不到可见窗口」并给出 `-Djava.awt.headless=false` 的提示。
- 版本区的 `poly-version-generator` 得认得出它声明的 profile
  （如 `source-snapshot`）；认不出时用 `--skip-check` 绕过前置检查，但**那是绕过**，
  该修的是 profile 定义。

## 常用参数

| 参数 | 作用 |
|---|---|
| `--area <相对路径>` | 只处理指定版本区，可重复 |
| `--dry-run` | 只列「每版是什么类型、入口类、文件数」，不编译不截图 |
| `--skip-check` | 跳过 `check_code.py` 前置检查（布局债未清时的逃生口） |
| `--out-root` | 编译输出根，默认 `<仓库根>/out` |
| `--submission-root` | 提交目录根，默认 `<仓库根>/提交` |
| `--java` / `--javac` / `--python` | 指定可执行文件 |

## 失败时怎么读输出

每个版本区打一张表，失败项逐条列出。对照处理：

| 症状 | 原因 |
|---|---|
| `找不到含 static void main 的类` | 该版没有入口，或入口写法特殊（如用了 `public static void main(String… args)` 之外的签名） |
| `编译失败` | 源码问题。先单独跑 `check_code.py` 拿到干净的编译错误 |
| `截图是纯色/空白` | 资源没加载。确认 `-cp` 含 `src/`、cwd 是版本根（`AssetLoader` 两条回退路径依赖它们） |
| `找不到可见窗口` | 程序没起来（异常早退），或在无桌面环境运行 |
| `GUI 进程超时` | 程序不是启动后就常态显示（如需要按键才开窗口）。调大 `RUN_TIMEOUT_SECONDS`，或给它加参数 |
| `运行期报错` | 控制台程序抛异常了。stderr 里的异常会原样带出来 |

## 调参

脚本顶部是常量区，都有注释：预热时长、超时、渲染图尺寸与字号、空白判定阈值。
**空白判定阈值别调高** —— 调高会把「资源没加载的黑图」放行，那正是这道检查要拦的。

## 与其它技能的分工

| 技能 | 管什么 |
|---|---|
| `poly-version-generator` | 版本区**放在哪、叫什么**（目录布局）；本技能的前置检查由它的 `check_code.py` 提供 |
| 本技能 | 让版本区**跑起来、截到图、打成可提交的包** |
| 报告类技能 | 交付说明、实验报告正文 |

本技能**不判断代码写得好不好**，也不改版本区里的任何源文件。
