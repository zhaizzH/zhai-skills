# 番茄扫榜 · 新书设定生成器

把「扫榜 → 挑标杆 → 拆前3章 → 出新书设定」全流程做成标准作业程序。产出的不是榜单搬运，而是**可落地的写作选题方案**。

## 一、目的与边界（重要）

- 这个技能服务的是**写作者的选题决策**：哪些题材好写、新书容易火、容易赚钱。
- 对标原则：**换皮不换骨**。保留标杆的"爽感骨架"（身份反差、金手指快速兑现、每章爽点+钩子、快速打脸），但世界观、主角身份、金手指机制、人物关系必须全部换掉，确保不构成抄袭。
- 产出新书设定前，**必须先给用户 2~3 种候选方向**，等用户选定后再生成最终完整文档。禁止直接只出一个方案。

## 二、前置条件

- playwright MCP 已连接（工具：browser_tabs / browser_navigate / browser_run_code_unsafe / browser_snapshot / browser_take_screenshot）；或直接用 curl 抓（番茄为 SSR 渲染，详情页 HTML 直接含书名/作者/简介/全部章节链接）。
- 番茄无需登录即可抓取完整榜单、详情与正文（2026-08-12 实测：curl 直抓首页/榜单/详情均 HTTP 200）。注意控制频率，避免触发风控。

## 三、番茄平台结构速查（2026-08-12 实测）

| 内容 | URL 模式 |
|------|---------|
| 官网首页 | `https://fanqienovel.com/` |
| 榜单页 | `https://fanqienovel.com/rank`（页内 tab：男频新书榜 / 女频新书榜 / 男频阅读榜 / 女频阅读榜 / 男频衍生 / 女频衍生等） |
| 书籍详情页 | `https://fanqienovel.com/page/{bookid}/`（bookid 为 19 位数字） |
| 章节阅读页 | `https://fanqienovel.com/reader/{chapterid}/`（chapterid 为独立数字 id） |
| 作者主页 | `https://fanqienovel.com/author-page/{authorid}/` |

- 榜单 tab 与书籍链接规律：详情页链接 `/page/{bookid}/`，章节链接 `/reader/{chapterid}/`（每章独立 id，非 bookid-chapterid 组合）。
- **详情页 HTML 直接包含全部章节目录**（`.chapter-item-title` 链接，实测 551 个 reader 链接全量在页内），无需翻目录页。
- 书名提取：`<title>` 形如 `惹金枝完整版在线免费阅读_惹金枝小说_番茄小说官网`；作者 `.author-name-text`；简介 `.page-abstract-content`。

## 四、标准流程

### Step 0 需求采集（开扫前必问，只问用户没说过的）

开始扫榜前先向用户确认约束，**用户已明确提供的不要重复问**；用户说"随便/你定"时记默认项，在报告里注明假设：

| 约束 | 默认项 |
|---|---|
| 榜单方向 | 男频（可指定女频，或两榜都扫） |
| 赛道偏好 | 无 → 扫完看题材分布，选占比最高的热门赛道 |
| 篇幅目标 | 长篇（≥13章/5万字，按卷规划） |
| 金手指方向 | 无 → 由标杆书启发，候选设定里换一个不重样的机制 |

产出《扫榜需求确认单》：一行列出"已确认项 + 默认项"，用户确认后进入 Step 1。用户直接给出明确指令时视作需求已确认，跳过确认单，把隐含假设写进 Step 2 报告开头即可。

### Step 1 扫榜（数据采集）

用 `browser_navigate` 打开 `https://fanqienovel.com/rank` 并切换到目标 tab（男频新书榜等），`browser_run_code_unsafe` 抓榜单；或 curl + grep 直抓（榜单 tab 若为 JS 切换则必须用浏览器）。抓每本书的：排名、书名、作者、分类、字数、热度、状态(连载/完结)、简介、最近更新、详情页链接 `/page/{bookid}/`。

注意：榜单页 tab 结构若与通用选择器不匹配，先用 `browser_snapshot` 看真实 DOM 再针对性写提取脚本。

### Step 2 分析榜单（情报提炼）

对 TOP20 做 5 个维度的观察，写进报告：
- **题材分布**：各大类占比
- **核心套路**：身份反差 + 金手指 + 打脸公式的共性
- **字数窗口**：新书期热度窗口对应字数区间
- **更新频率**：上榜书是否当日更新（稳定日更是门槛）
- **标题模板**：简介是否用 `【卖点1+卖点2+卖点3】` 标签前缀
- **热度断层**：头部是否断崖领先

### Step 3 挑标杆（关键决策）

1. 选**热门且好写、变现强**的赛道（参考 Step 2 题材分布）
2. 在该赛道内选**排名最高、热度最猛**的一本
3. 优先选**标题本身就是钩子**的书（反套路标题是教科书）
4. 记录选择理由（赛道占比 + 排名 + 热度 + 特色）

### Step 4 看简介

打开详情页 `/page/{bookid}/`，抓 `.page-abstract-content` 简介全文 + 标签（书名取 `<title>`，作者取 `.author-name-text`）。
- 简介选择器不确定时，用通用方法：遍历 `p, [class*="intro"], [class*="brief"], [class*="abstract"]` 等文本块，找 40~900 字区间的正文块。
- 简介能告诉你：主题、卖点、金手指机制、人物关系——这是"这本书讲什么"的地图。

### Step 5 抓前 3 章

1. 详情页 HTML 已含全部章节链接（`.chapter-item-title`，格式 `/reader/{chapterid}/`），直接取第 1、2、3 章 URL，无需翻目录页、无需点"开始阅读"。
2. **抓正文用「渲染截图 + 视觉模型还原」方案**（番茄有字体混淆反爬，curl/Playwright 抓的 textContent 是乱码，但浏览器渲染后像素是正常文字）：
   - `npx playwright screenshot --wait-for-timeout 8000 --viewport-size=800,1400 "https://fanqienovel.com/reader/{chapterid}" /tmp/fq_ch.png`（本机首次需 `npx playwright install chromium`）
   - 然后用**视觉模型**（vision_analyze / qwen-mm read_image）读图：提示视觉模型「逐字读出正文前 N 句完整文字，不要省略」——实测还原度 100%（2026-08-12）。
   - 长章节可分屏截取（viewport 高度调小分多次截图，或用滚动截图工具）。
3. curl 直抓可作快速通道：正文约 88% 可读（被混淆的多是高频字，配合上下文可推断），但**书名/榜单标题 100% 混淆不可用**。
4. 每章约 2000-3000 字，3 章共约 6000-9000 字，完整存档原文（`原文-标杆书-{书名}-前3章.md`）。

### Step 6 拆解（核心产出）

对照以下 checklist 逐项分析，写成拆解报告：
- **开局钩子**：第 1 句是否即高潮？背景设定是倒叙补还是先铺垫？（标杆做法：绝不铺垫，第一句就是冲突）
- **金手指兑现**：第几章兑现？爽点隔不隔夜？
- **每章结构**：每章是否有 1 个完整爽点 + 1 个章末钩子？N 章 = N 次追读冲动
- **打脸节奏**：反派何时登场、多久被收拾？
- **设定为爽服务**：金手指的一切规则是否只指向一个爽点？有没有多余设定？
- **文风**：短句密度、对话占比、笑点/反差梗。

### Step 7 产出候选设定（必须多选，用户拍板）

拆解完成后，**在对话中**先给出 2~3 种候选新书设定方向，每种包含：
- 题材/世界观一句话
- 一句话概念钩子
- 主角身份 + 核心反差
- 金手指机制（换一个，不抄标杆的）
- 女主/关键人物
- 前 3 章各章钩子简述

然后**明确询问用户选哪一种**（或要不要调整某个方向），等用户答复后再进入 Step 8。禁止跳过选择直接出文档。

### Step 8 输出最终新书设定文档

用户选定后，先执行**开新书目录流程**（见「五、输出与落盘约定」）：`mkdir -p 小说扫榜/<书名>/{正文,材料}`，把 `小说扫榜/扫榜/` 下的扫榜产物移入 `小说扫榜/<书名>/材料/`。然后生成完整设定文档（`小说扫榜/<书名>/材料/新书设定-<书名>-<日期>.md`），结构：
1. 一句话核心卖点
2. 书名（含备选 2~3 个，带标题钩子分析）
3. 主角设定（身份、性格、动机、核心反差）
4. 女主/重要配角
5. 反派与大线（埋好长期冲突）
6. 金手指机制（规则、成长曲线、爽点）
7. 世界观/场景
8. 前 3 章大纲（每章：钩子、爽点、章末悬念）
9. 对标对照表（哪些算同构方法论、哪些是合法差异化，讲清"不抄"边界）
10. 写作执行提醒（沿用拆解出的章法 checklist）

## 五、输出与落盘约定

- **每本小说一个根目录**：`小说扫榜/<书名>/`，内含 `正文/` 与 `材料/` 两个子目录。
- 扫榜期产物（`调研-` / `原文-` / `拆解-`）统一存 `小说扫榜/扫榜/`（固定目录，文件名带日期区分批次）；用户选定书名、进入 Step 8 时创建 `小说扫榜/<书名>/材料/`，把扫榜产物 + `新书设定-<书名>-<日期>.md` + 后续三份材料（角色DNA/故事大纲/情绪节拍表）全部放入该目录。
- 正文按章写入 `小说扫榜/<书名>/正文/第NN章-<书名>.md`。
- 续写状态文件：`小说扫榜/<书名>/材料/novel-<书>-state.md`。
- 文件名带日期（跨天区分）；原文必须完整一字不改；拆解和新书设定是加工产物。
- 完成后用 present_files 展示关键文件（拆解报告 + 新书设定 + 原文）。

## 六、踩坑记录（实测）

- **字体混淆反爬（关键）**：书名 100%、正文 ~12% 高频字被替换为私有区 Unicode 码点，浏览器靠动态字体（bytetos CDN woff2，内容寻址文件名）显示。curl/Playwright 抓的 textContent 均为乱码；字体子集化 + gid 命名无字符信息，字形比对破解成本高。**推荐方案：渲染截图 + 视觉模型读图**（实测还原度 100%）。
- 榜单 tab 若为 JS 动态加载，curl 拿不到全部榜单数据 → 用浏览器渲染后抓取（/rank 实测 HTML 含 tab 文字与书籍链接，抓取时验证数据量）。
- 详情页书名在 `<title>`（含"完整版在线免费阅读"等后缀），清洗时去掉后缀只留书名；榜单内书名是混淆字体，需视觉/映射还原。
- 章节链接每章独立 `/reader/{chapterid}/`，不是 bookid 组合——从详情页 `.chapter-item-title` 直接取（551 个链接全量在页）。
- 章节页底部有「扫码下载 APP / SVIP 网页畅读」提示，VIP/付费章节需登录，免费章节可直接抓。
- 控制抓取频率（每请求间隔 2-3 秒），避免触发风控/验证码。

## 七、可扩展

- 同一套流程可平移到其他平台（起点、七猫、晋江），只需替换：榜单 URL、页面选择器、输出目录。
- 女频：榜单 tab 切到女频新书榜/女频阅读榜，题材分布结论会不同（言情/甜宠主导），拆解时注意赛道差异。
